# neato port (Graphviz 16.1.0)

`layout=neato` (and `-Kneato`) now runs a function-by-function port of
`lib/neatogen` plus the shared infrastructure the other non-dot engines need.
All eight engines now have their own ports; the old `force_circular` stand-ins are gone.

Entry point: `graphviz_pure_layout::neatogen::neatoinit::neato_layout(&mut Graph)`.

## Fidelity

Re-measured on 2026-10-28 with `gv-diff --golden tests/golden/neato
--baseline tests/golden/neato-baseline.portable.json --worst 0 tests/neato`, without
`--update`: **442 / 445 exact**, with no regression. The three errors are inputs C crashes on,
so they have no C layout to compare against. All stable neato inputs match byte for byte in
`gv-diff e2e`; the current cross-engine results are in [README](../../README.md#fidelity-against-c-graphviz-1610).

Most layouts are bit-identical to C: floating-point expressions follow the C
source as compiled by clang with `-ffp-contract=on` (an expression `a*b + c`
is computed as `fma(a, b, c)`, a `float*float` product added to a `double` is
rounded to `float` first, `x - y*z` is `fma(-y, z, x)`), and every random
number, sort and container order reproduces macOS libc/cgraph behaviour.

### Validation

- `cargo run --release -p graphviz-pure-diff -- --golden tests/golden/neato --baseline tests/golden/neato-baseline.portable.json tests/neato`
  (ratchet test: `crates/graphviz-pure-diff/tests/neato_fidelity.rs`).
- Corpus: `tests/neato/*.gv` is generated by `scripts/gen-neato-corpus.py`
  (fixtures and undirected wild graphs with `layout=neato` forced, plus
  hand-written cases for modes, models, start, pos/pin, len/weight, overlap
  modes, sep/esep, splines, pack/packmode, labels, ports, ratio/size, random
  graphs up to 120 nodes). Goldens: `scripts/gen-golden.sh` writes
  `tests/golden/neato/`. Cases whose C output is not reproducible run to run
  (`start=rand` uses the clock; `ngk10_4`'s two-way multi-edge pair ends on the boundary
  of GTS's triangulation, so the tie is broken by the order GTS returns its faces) and
  `model=circuit mode=KK` (segfaults in C 16.1.0) are excluded.
- A locally built, instrumentable C copy lives in `~/src/gv-ref/build-neato`
  (`run.sh`); it matches Homebrew's output to the last printed digit on almost
  all files.

## Deviations

- `overlap=ipsep` is a no-op in C's adjust step (handled during `mode=ipsep`).
- The `makeMultiSpline` router's triangulation numbers faces in creation order,
  not GTS's pointer-hash order (see below).
- VPSC's `std::set<Block*>` and scanline `NodeSet` pointer order are modelled
  as creation order ("Ties by address" below).
- When `IncVPSC::satisfy` fails during `mode=ipsep` ("Cycle Error!",
  "Unsatisfied constraint"), C aborts on the uncaught exception. The port, whose
  block order can fail where C's heap order does not, reads the positions back
  and goes on, as before. After more than 500 cycle errors (`MAX_CYCLE_ERRORS`),
  it warns and ends the stress loop of that component. Before #197, corpus files
  that finished within 10 s reached at most 241 (#197;
  `ipsep_vpsc_cycle_error_ends_the_layout` in `crates/graphviz-pure-cli/tests/cli.rs`).
- The VPSC solver reuses the slots of blocks that no variable belongs to and that are not
  in `Blocks`. C frees or leaks these; the port kept them all, so memory grew with every
  split (#197, #222). Block order comes from a creation counter, not the slot.
- Prism's Delaunay triangulation is a Bowyer–Watson port, not GTS; the edge
  set matches for points in general position, but ties between co-circular
  points and the matrix entry order may differ (all prism corpus files are
  still exact).
- `start=random` without a seed uses seed 1 (C uses the clock).
- `model=mds` with `mode=KK` indexes by layout id where C uses 1-based
  `AGSEQ` (undefined behaviour in C).
- Engines/attributes outside neato's code paths (`-n` / `Nop`, `dim>2` output
  via `z`) are not covered. `splines=ortho` runs the `lib/ortho` port through the ortho branch of
  `spline_edges_` (`neatosplines::spline_edges_route`: `makeObstacle(isOrtho)`,
  `Plegal_arrangement`, `orthoEdges` on the component being routed,
  `addEdgeLabels`), shared by neato, twopi, circo, sfdp, fdp and osage (opus5.5/dot-phase3);
  `-Gsplines=ortho` over the first 120 files of each of `tests/neato`,
  `tests/twopi`, `tests/circo`, `tests/sfdp` matches C except where the
  layout itself differs.
- Renderer changes made for C parity (`graphviz-pure-render`): edges without a spline get
  no `pos`; `arrowhead/arrowtail=none` produce no `e,`/`s,` point; degenerate
  graph boxes print as computed; clusters with no layout box get no `bb`.
  `gv-diff` now compares `bb` only for clusters.

## Handoff: shared API for fdp / sfdp / twopi / circo / osage / patchwork

Typical engine skeleton (mirrors `neato_layout`):

```rust
let src = graph.clone();
let mut g = LGraph::new(&src, 2, EdgeType::Line);   // graph_init + node/edge init
// ... compute g.nodes[n].pos (inches) for the nodes of a Sub ...
let (mut ccs, pinned) = pack::pccomps(&g);          // or pack::ccomps
neatogen::adjust::adjust_nodes(&mut g, &sub);       // overlap=... (twopi, circo)
neatogen::adjust::remove_overlap_as(&mut g, &sub, Some(flag)); // fdp
neatogen::neatosplines::spline_edges(&mut g, &mut sub, is_root); // translate + route edges
pack::pack_graphs(&mut g, &mut ccs, &pinfo);         // packGraphs with doSplines
common::utils::compute_bb(&mut g, &mut root, true);
common::postproc::gv_postprocess(&mut g, true);       // labels, xlabels, translation
g.write_back(graph);
```

Key types and conventions:

- `LGraph<'a>` borrows the parsed `Graph`; `nodes[i].pos` is `ND_pos` (inches,
  `ndim` components), `coord` is `ND_coord` (points, set by
  `neato_set_aspect`), `lw/rw/ht/width/height/shape` come from exact C node
  geometry. `edges[e]` carries `dist`, `factor`, ports, labels, `spl`.
- `Sub` is a node-induced subgraph (`nodes` sorted by sequence, `member`
  mask, `bb`, top-level `clusters`). `g.root_sub()` is the root.
- Iteration: `g.outs(sub, n)` = `agfstout..agnxtout` (ordered by head
  sequence, then edge), `g.ins`, `g.all_edges` = `agfstedge..agnxtedge`,
  `g.find_edge` = `agfindedge`.
- Randomness: `cutil::drand48`/`srand48` and `cutil::rand`/`srand`, on one
  state per run, as C's globals are process-wide: a graph's unseeded draws
  continue from the earlier graphs' (#290). `cutil::RkState`; sorting with
  `cutil::qsort_by`.
- Clusters: `g.clusters` (`LCluster { subgraph, bb, label, label_pos, border, children }`)
  and `g.root_clusters` are the C `GD_clust` arrays; `write_back` copies their
  boxes, and unregistered clusters keep an input `bb` attribute.
- Edge routing: `neatosplines::spline_edges0` handles `splines=` line,
  polyline, spline (pathplan), curved, self loops and multi-edges for any
  `Sub`; `common::splines::clip_and_install` is the generic installer (no
  `ND_rank`/virtual-edge logic yet: dot's port should add that).
- Overlap removal: `neatogen::adjust::{graph_adjust_mode, get_adjust_mode,
  remove_overlap_with}` with `AdjustData`; prism is in `neatogen::overlap`,
  Voronoi in `neatogen::voronoi`, scaling in `neatogen::scadjust`.
- sfdp can reuse `sparse::SparseMatrix` and
  `sfdpgen::post_process::StressMajorizationSmoother`.

## Gap closure (opus5.5/neato-gaps)

### Generic network simplex and `constraint.c` (`overlap=ortho*`, `portho*`)

`lib/common/ns.c` lives once, in `common::ns`, generic over the `NsGraph`
trait (the node/edge fields `ns.c` reads: `ND_in/out`, `ND_tree_in/out`,
`ND_rank/low/lim/par/priority/mark/subtree`, `ED_minlen/weight/cutvalue/
tree_index`, `GD_nlist`, `agget`). `dotgen::ns` implements it over dot's fast
graph; `NsData` is a standalone graph. `-Tdot` of all 1148 corpus files was
byte-identical before and after the move.

`neatogen::constraint` ports `cAdjust`: `initItem` (integer boxes in tenths of
a point, fused `ROUND`), the cdt `Dtobag` sort (`cutil::DtTree`, a faithful
splay insert: the position of equal keys depends on the tree shape),
`mkConstraintG` (chain over distinct coordinates plus visibility constraints
merged through `mapGraphs`, strict `agedge`), `mkNConstraintG` (pairwise
constraints, weight 100 on real edges via `agfindedge`), and
`rank(cg, 2, INT_MAX)`. 43 `hw3_*ortho*` cases.

### VPSC (`overlap=vpsc`) — `graphviz_pure_layout::vpsc`, `neatogen::quad_prog_vpsc`

Graphviz only instantiates `IncVPSC` (`newIncVPSC`), so the port covers
`IncVPSC::solve/satisfy/splitBlocks/moveBlocks/mostViolated`, `Block`
(`merge`, `split`, `splitBetween`, `findMinLM(Between)`, `compute_dfdv(_between)`,
`populateSplitBlock`, `cost`), constraint generation (`generateX/YConstraints`
with libc++ `std::sort` of the scanline events, neighbour sets) and the C
bridge. Unreachable: non-incremental `VPSC`, `Blocks::mergeLeft/Right/split`,
the block constraint heaps, cycle checks. C++ orders that depend on pointers
(`Blocks : std::set<Block*>`, `CmpNodePos` ties) use allocation order; a block
split mid-iteration is visited when it sorts after the current block, as with
`std::set`. A leaked block (C's `satisfy` merges into a block it never inserts
into `bs`) is reproduced. `removeoverlaps`/`vpscAdjust` run on `float`
coordinates as in C. 11 `hw3_vpsc_*` cases; one `mode=ipsep` case whose C
output changes run to run (pointer order) is excluded from the corpus.

#### Ties by address (#225)

C's output under `mode=ipsep overlap=vpsc` with clusters depends on its allocator. VPSC's
constraint generation keeps its scanline in a `std::set<Node*, CmpNodePos>`, ordered by
position with ties broken by pointer (`lib/vpsc/generate-constraints.cpp:76-84`), and
`Blocks` is a `std::set<Block*>`. Ties are common here: `initCMajVPSC` takes the last
`2 * nclusters` nodes as the clusters' boundary variables (`lib/neatogen/quad_prog_vpsc.c:204-205`),
and a member among them goes into the cluster's list twice, with the member's box and with
the container's (`:414-415`). The port does the same.

The port's order is monotone creation order. A scanline node's address is its index in the
`generateX/YConstraints` call that makes it (`NodeKey`). A block's address is a counter that
only grows over the solver's life (`Solver::next_addr`), whereas C's `~Blocks` frees each
`IncVPSC`'s blocks. C's addresses come from macOS's allocator instead: each call frees its
`make_shared` nodes with its event vector, the next call reuses those chunks, and the
per-CPU magazines it draws from make the result change from run to run. With
`MallocNanoZone=0 MallocMaxMagazines=1`, C is stable on each input but gives yet another
layout on some.

Measured on `tests/vpsc-ties/` (`scripts/gen-vpsc-ties.py`: chains with one-node or
two-node clusters at the start, middle and end, random graphs with clusters, and #225's
input) and the corpus's 5 `ipsep`/`vpsc` cluster files, 46 inputs, with
`scripts/vpsc-ties-measure.py` (`tests/vpsc-ties/outcomes.tsv`). C ran with the port's math,
10 times each:

| C | Inputs | The port's output |
|---|--:|---|
| fails (`Cycle Error!`, segfault, `bitarray_set`'s assertion; #185, #168) | 28 | no panic (`issue225_vpsc_tie_inputs_c_fails_on_do_not_panic`) |
| one output | 9 | equals it on 8 |
| varies | 9 | is one of C's outputs on 7 |
| any of the 18 it lays out, with `scripts/c-bump-malloc.c` (addresses in creation order) and address randomisation off | 18 | equals it on 18 |

The last row is the decision's basis: apart from addresses, the port computes what C
computes, and with addresses in creation order C's output is the port's. The one input
where C is stable over 10 runs and the port differs, `chain-n8-k2-last.gv`, is no exception:
with the bump allocator C gives the port's output, and with macOS's allocator C varies on
it too (2 of 30 runs gave another output). Ordering later objects at lower addresses, as
reusing freed chunks would, was also measured: it matches C's most frequent output on some
inputs and loses on others. The port keeps creation order, the same on every platform
(`issue225_vpsc_ties_follow_creation_order`, `node_key_breaks_position_ties_in_creation_order`).

### `mode=hier` (DiG-CoLa) and `mode=ipsep` — `neatogen::digcola`, `neatogen::cola`

`stress_majorization_with_hierarchy`: `compute_y_coords` (CG on uniform
weights, `init_vec_orth1` with `rand()`), `compute_hierarchy` (libc `qsort`),
smart init through `IMDS_given_dim` (classical MDS power iteration with
`rand() % 100`), `levelsgap`, and `constrained_majorization_new_with_gaps`
for the y axis (including C's `lev[right]` indexing by position).
`stress_majorization_cola`: cluster dummy variables and the extended
Laplacian, `initCMajVPSC` for `diredgeconstraints=true|hier` (DiG-CoLa level
boundaries; C loops forever when there is no boundary, the port skips),
`overlap=ipsep` node-size ramp and `overlap=vpsc` post-pass, gradient
projection in `float`. `cluster_map` maps top-level clusters of the root, keeping only the members
in the component being laid out (C asserts on a member in another component, #168).
`generateNonoverlapConstraints` sizes its boxes before taking off the cluster
dummies, as C does: the `overlap=vpsc` post-pass passes only the real nodes, so
cluster members among the last `2 * nclusters` read zeroed boxes. With fewer
real nodes than that C segfaults; the port passes the dummies too (#185).
17 `hw3_hier_*` and 12 `hw3_ipsep_*` cases.

### `makeMultiSpline` — `neatogen::multispline`

Homebrew's build links GTS, so `spline_edges_` sends multi-edges and edges with
boundary ports (`splines=true|polyline`) to the router before falling back to
per-edge `makeSpline`/`makePolyline`. `mkSurface` is a constrained Delaunay
triangulation with exact predicates (Bowyer–Watson inside GTS's enclosing
triangle, Sloan flips for each constraint, Lawson restoration with fixed
constraints) and GTS's hole rule (drop faces whose constraint edges run against
the CCW face orientation; interior faces without a constraint side survive, as
in C). GTS's own `triangulate_polygon` yields the same constrained Delaunay
triangulation unless four points are co-circular. Face and neighbour numbering
follow creation order, not GTS's hash order (#35), and each face's corner order
is the port's own, not GTS's (#28); both only matter for exact ties in the
triangle shortest path. Validated with `Pshortestpath`/`Pobspath`
interposed into Homebrew's `dot` (`DYLD_INSERT_LIBRARIES`): guiding polygons
match C. 13 `hw3_ms_*` cases (fan-out of 2–4 multi-edges, failing fan-outs,
compass ports, random graphs with multi-edges and ports).

### `gv16_graphs_b15` dynamic record ports

Fixed upstream by the dot-splines branch's single rankdir-aware
`common::ports` (record field sides for dynamic ports); the main corpus file is
exact and `hw3_ports_b15(_splines)` check the same ports through neato.

### overlap=scalexy with coincident nodes

`overlap=scalexy` is `scAdjust(g, 0)` (`lib/neatogen/constraint.c`).
`computeScaleXY` sorts each overlapping pair's scale requirements and picks
the candidate whose product is smallest. A pair at the same position, or so
close that the ratio overflows, is stored as `(HUGE_VAL, HUGE_VAL)`
(`mkOverlapSet`), so every candidate's cost is non-finite and C fails
`assert(bestcost < HUGE_VAL)` (`constraint.c:729`) with no output. neato
(`-n` through `init_nop`, and a full layout through `removeOverlapWith`),
fdp (`removeOverlapAs`; `maxiter=0` or a pin the solver does not separate),
circo and twopi (`adjustNodes`) and sfdp (`removeOverlapWith`, when
`overlap` is not prism) all reach that function.

The port's `compute_scale_xy` (`neatogen/scadjust.rs`) returned the
non-finite scale, and the positions became `nan` (`inf * 0`) and `inf`.
Nodes a hair apart still have a finite scale: `0.001` points apart, C prints
a graph about 612 inches tall. At exact equality no finite scale separates
them. `scAdjust` already returns 0 when it cannot help (no overlapping pair,
or `compress` finds one), and the positions computed before the scale are
finite. The port does that: it keeps them, warns
`overlap=scalexy has no finite scale; scaling skipped`, and exits 0. A pair
that coincides on only one axis still scales, as C does.

### Full-pipeline (`-Tsvg`) fixes found with `gv-diff e2e`

- Edges whose endpoint is a subgraph (`a -> {B A}`) are created in node
  sequence order, as cgraph's grammar walks `agfstnode(subg)` (parser).
- Unplaced edge labels (`ED_label(e)->set == false`) print `lp` but are not
  drawn (`EdgeData::label_unplaced`).
- Clusters the layout did not register (`GD_clust`) keep their input `bb` but
  are not drawn (`ClusterReg::Unregistered`).
- `RADIANS(d)` is `d/180*M_PI` (fused when added to `atan2`), not
  `to_radians()`.

### Remaining gaps

- Prism (`overlap=false`, default for sfdp): GTS's edge enumeration order
  (pointer hashing) changes summation order in the solver by an ulp; visible
  only in printed digits (7 arrow graphs in e2e) and in chaotic cases.
- `makeMultiSpline` triangle centres (issue #28): `triCenter`
  (`multispline.c:391`) sums a face's corners in the order
  `gts_triangle_vertices` returns them. The GTS manual documents only that
  this order "respects the orientation of t" and that `e1` joins `v1` and
  `v2`; which corner comes first depends on which edge GTS's construction
  stored as `t->e1`. That is deterministic in C, but it follows GTS's
  insertion and flip history, which the port's CDT does not replay. The port
  can start at a different corner on every face (all 22 in the repro), so a
  centre can differ by an ulp. When two triangle paths tie exactly in C
  (mirror-image obstacles), that ulp picks the other side and `tweakEnd` can
  move the end point 0.1pt. With C's corner order the port's `tri_path`
  picks C's path, so the tie-break itself matches. See also #35 (face order).
  Tracked by the ignored test `neato_polyline_compass_port_routes_like_c`.
- A two-way multi-edge pair (`13 -- 24` and `24 -- 13` in
  `tests/wild/gv16_undirected_ngk10_4_793340.gv`, `-Kneato -Tplain`) is routed
  from the same end in C and the port (#438). `GVDUMP` instrumentation of
  `genroute` on both sides shows the same representative edge `(13,24)`, the
  same corridor vertex sequence (`t=6`, 12 vertices), and coordinates ~1e-4 pt
  apart from the prism/GTS order above. The failing `Pshortestpath` endpoint
  sits on the corridor boundary, so "point in triangle" is an exact tie: over
  10 identical runs of C with the port's math, the input gives three outcomes
  — fail the first edge (edge `(13,24)`), fail the second (edge `(24,13)`),
  or no warning at all — with different stdout, and the
  `source`/`destination point not in any triangle` wording flips
  independently. The port deterministically prints the second variant, byte
  for byte one of C's own outputs (stock Apple-libm C prints it on every
  run), including the fallback after a mid-loop `genroute` failure, which
  keeps the already-routed first edge's spline and appends the per-edge
  `makeSpline` spline to it (a 14-point plain line). Closed as the #35 tie.
- `splines=ortho` in neato is ported through the shared `lib/ortho` implementation.
- VPSC/IncVPSC pointer-ordered containers follow creation order; C's output
  follows its allocator and is not reproducible on some `mode=ipsep` inputs
  ("Ties by address" above).
