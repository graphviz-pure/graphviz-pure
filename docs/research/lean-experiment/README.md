# Experiment: improvement through math proofs

Milestone: [Improvement through Math Proofs](https://github.com/graphviz-pure/graphviz-pure/milestone/10).
Started 2026-11-03. Survey that motivated it: [`../lean-bend-survey.md`](../lean-bend-survey.md).

## The bet

graphviz-pure must reproduce C Graphviz 16.1.0 byte for byte. That turns every speedup into an
equation: the fast path must return the same integers, or the same IEEE doubles through the same
rounding sequence, as the mirror of C's code. The repo already writes such arguments in prose
(`docs/perf/ns-cut-sets.md`, `mincross-scans.md`, `circo-crossings.md`, `spline-cubic-634.md`) and
checks them at runtime with `*-check` Cargo features. The bet is that writing them in Lean 4 instead:

1. finds gaps the prose missed (a finding even when the code is right),
2. lets us ship speedups whose equivalence argument is too fiddly to trust in prose
   (incremental circo deltas, the network-simplex leave-edge index, float reuse in spline routing),
3. is cheap enough to be a merge gate, with the proof stated over the shipped Rust via
   Rust-to-Lean extraction (Aeneas), not over a hand-written model.

The experiment is scoped to measure all three. It ends with a write-up of what the proofs bought
in wall time and in bugs, and what they cost in hours.

## Working on it

Lean lives outside the Rust toolchain. On the shared machine it is installed under
`/jobs/work/gvp-lean/` (elan, Lean 4.35.0, the Aeneas checkout); `scripts/proofs/lake.sh` finds it
through `GVP_LEAN_HOME`. Elsewhere, install [elan](https://github.com/leanprover/elan), and the
`lean-toolchain` file selects the version.

```sh
scripts/proofs/lake.sh exe cache get   # once: Mathlib's prebuilt oleans
scripts/proofs/lake.sh build           # every GvpProofs/**.lean must compile, no sorry
```

Adding a proof: create `proofs/GvpProofs/<Engine>/<Name>.lean`, state the theorem in the
"fast path = C-mirror path" shape, keep the matching `*-check` feature until the file is sorry-free,
then say in the PR which runtime check the proof retires. Branch names follow the perf scheme:
`proofs/<issue>-<slug>` for Lean-only changes, `perf/<issue>-<slug>` when Rust changes too.

Lean version policy: pinned to the toolchain Aeneas's Lean backend requires (`v4.35.0` on
2026-11-03) and to the Mathlib tag of the same name. Bump both together, in their own PR.
