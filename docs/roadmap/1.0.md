# graphviz-pure 1.0

1.0 is "the current port without known bugs", with a public API stable enough that the work
after it (speed, memory, idiomatic Rust) can happen behind it without breaking anyone. This
document says what that means in checkable terms, what stands between master and it, and what
the maintainer decided. Progress is tracked in the
[`1.0` milestone](https://github.com/graphviz-pure/graphviz-pure/milestone/7).

Every number below was measured on master at `f9c2fd1d` (0.2.2) on 2026-10-27. The command
that produced it is given next to it or under [How this was measured](#how-this-was-measured).

## Definition of done

1.0 ships when every box below can be ticked. Each one is a command or a query, not a judgement.

### Fidelity

- [ ] **F1. Every stable corpus input is byte-identical to C.** `gv-diff e2e` reports
  `identical == files` for every corpus, and the layout (`gv-diff`, eight baselines) and render
  (`gv-diff render`, seven formats) ratchets report no inexact file outside the accepted list in
  F2. *Today: met* (see [Where fidelity stands](#where-fidelity-stands)).
- [ ] **F2. Every input that is skipped or inexact has a recorded cause in an accepted class**:
  C nondeterminism or undefined behaviour, a C crash or assertion, C's error path, or the
  platform libm (docs/versioning.md). The cause is on the What's left page or in
  `docs/porting/`. *Today: 12 of the 14 skipped inputs have one* (#502).
- [ ] **F3. No open fidelity bug in the port.** No open issue labelled `fidelity` or `bug` lacks
  `wontfix`. *Today: 7 open, all in progress* (#475, #476, #488, #489, #490, #494, #496).
- [ ] **F4. A differential fuzz round on the 1.0 candidate**, of at least 6,000 new seeds over
  all eight engines, has every differing case fixed or triaged into an F2 class (#511).
- [ ] **F5. What's left is true.** Every `tests/fuzz-open/` entry and manifest flag matches
  its GitHub issue, and every open fidelity issue or accepted difference is listed (#502).
- [ ] **F6. `-Tsvg_inline` and `-Tcmapx` are byte-identical to C** on the render corpus, and
  README and versioning.md list the formats the port lacks ([D6](#decisions), #524).

### Robustness

- [ ] **R1. No open `crash` issue.** *Today: met* (7 `crash` issues, all closed).
- [ ] **R2. The pre-release ClusterFuzzLite run passes on the 1.0 release branch**, as
  docs/releasing.md already requires for every release.
- [ ] **R3. The panic-site ratchet runs in CI and no count is above `tests/panic-sites.tsv`.**
  *Today: met* (9,985 sites against a baseline of 9,988). 1.0 has no target count
  ([D5](#decisions)).
- [ ] **R4. Coverage-guided fuzzing runs weekly** on a schedule that keeps its corpus alive,
  besides the pre-release gate ([D7](#decisions), #527).

### Rust and JS API

- [ ] **A1. The stable surface is declared and is only the facade and raster**
  ([D1, D3](#decisions), #520): docs/versioning.md and the crates' docs declare core, parser,
  geom, layout and render implementation crates, which the facade pins with `=`. The facade's
  `Graph` has no public fields and no accessors. The CLI-only helpers are gone from the facade,
  and no stable type implements serde (the derives are gone from core's graph types too).
- [ ] **A6. The stable types can grow in a minor** ([D2](#decisions), #521): the stable enums
  and `LayoutOptions` are `#[non_exhaustive]`, options have a builder, and the error is an
  opaque struct with a `#[non_exhaustive]` kind, which raster also returns.
- [ ] **A7. The library never writes to stderr** ([D14](#decisions), #522): diagnostics are
  returned as values, and the CLI's stderr is still byte-identical to C.
- [ ] **A8. The JS API is idiomatic** ([D10](#decisions), #523): it throws `Error` objects
  with the exit status, returns arrays and objects, and ships a checked `.d.ts`.
- [ ] **A9. `-V` has C's shape**, `graphviz-pure - graphviz version 16.1.0 (graphviz-pure
  X.Y.Z)` ([D13](#decisions), #526).
- [ ] **A2. CI checks the API.** `cargo semver-checks` runs against the last release for the
  stable crates (#507).
- [ ] **A3. The declared minimum Rust version is true and tested in CI**, and is no newer than
  current stable minus two releases ([D4](#decisions), #504).
- [ ] **A4. Nothing deprecated or promised for removal is left** in the published crates (#506).
- [ ] **A5. The wasm package reports itself correctly**: its `version()` and
  `supportedFormats()` (#505).

### Docs are true

- [ ] **D-2. Every number in README.md, the site and docs/ comes from the current ratchets**,
  and nothing describes something already fixed or shipped as pending (#508).
- [ ] **D-3. docs/versioning.md covers every channel and states its exceptions** (#509).

### Security and licensing

- [ ] **S1. SECURITY.md matches the workflows**, and the READMEs say that SVG from untrusted
  DOT is untrusted markup (#510).
- [ ] **S2. The supply-chain job passes**: `cargo deny`, `THIRD-PARTY-LICENSES.md` up to date,
  and the crate notices in place. These are existing CI checks; they must be green on the
  release commit.
- [ ] **S3. The supported-versions policy for 1.x is written down** ([D9](#decisions), #510):
  the latest minor gets fixes, and 0.x gets none after 1.0.0. SECURITY.md also says that
  layout cost is unbounded and that services need their own limits ([D8](#decisions)).
- [ ] **S4. The licence metadata matches what each package ships** ([D12](#decisions), #525):
  core and geom `EPL-2.0 AND MIT`, raster `EPL-2.0 AND OFL-1.1`, npm and JSR
  `EPL-2.0 AND MIT`, with the licence texts in each package.

### Release

- [ ] **P1. 0.2.2 is out.** Release PR #501 was merged on 2026-10-26, but there is no `v0.2.2`
  tag and no channel has 0.2.2 (`gh release view v0.2.2`: release not found; crates.io, npm,
  JSR, PyPI and Wasmer all report 0.2.1). The maintainer tags the merge commit (docs/releasing.md).
- [ ] **P2. 1.0.0 is published on every channel docs/channels.md marks ready**, and
  `scripts/release-verify.sh` passes for each.

## Where fidelity stands

The reference is C Graphviz 16.1.0, built without Pango and computing with the port's math
functions (`scripts/dot-portable-libm.sh`). Every input with a stable C output matches C byte
for byte:

| Check (command) | Result |
| :--- | :--- |
| Full `-Tsvg` (`gv-diff e2e --list`) | 2,595 / 2,595 identical; 14 inputs skipped (below) |
| Main layout corpus (`gv-diff --baseline tests/golden/baseline.portable.json`) | 566 / 566 exact |
| Engine corpora (`gv-diff --golden tests/golden/<e> … tests/<e>`), exact | neato 442/445, sfdp 297/297, circo 282/282, twopi 281/289, fdp 386/388, osage 180/180, patchwork 141/141 |
| Renderers on C's layouts (`gv-diff render`) | svg, xdot, dot, json0 587/587; json 551/551; plain, plain-ext 577/577 |
| Against stock C on macOS (informational; `tests/golden/e2e-baseline.portable.json`) | 2,474 / 2,594; the 120 others differ only through Apple's libm (#40) |

The inputs that are not compared, and why:

| Inputs | Class | Where recorded |
| :--- | :--- | :--- |
| twopi: `fx_arrows` and the 7 other arrows graphs (e2e skip; the 8 inexact twopi layouts) | C nondeterminism (floating-point tie in routing) | #41, `tests/fuzz-open/032-*` |
| neato: `fuzz_ipsep_cluster_other_component`, `fuzz_ipsep_vpsc_clusters` (C exits 134), `fuzz_nan_pin_edge` (C exits 139) | C crashes; the port draws them | README, crash tests in `crates/graphviz-pure-cli/tests/cli.rs` |
| fdp: `wild_gv16_undirected_ngk10_4_793340` | C reads uninitialised memory | docs/porting/neato.md |
| fdp: `wild_gv16_graphs_b51_33bcb0` (inexact layout; its `-Tsvg` matches) | C address-dependent cluster layout | #34, #476 |
| fdp: `wild_gv16_infosrc_plugins_1a797f`; sfdp: `wild_gv16_linux_x86_neatosplines_neato1_448ced` | C unstable over 5 runs on macOS when the references were made | **cause not recorded** (#502) |
| `-Tplain`, `-Tplain-ext`: 10 Latin-1 references | C use-after-free in `canon` | #42 |
| `-Tjson`: 36 layouts with no C reference | no C output to compare | `crates/graphviz-pure-diff/src/render.rs` |

**Accepted differences outside the corpora.** Closed as not planned, with the reason recorded:

- #32 to #43 are fuzz-open entries `023`–`034`: C undefined behaviour,
  crashes, and clock- or address-dependent output. #40 is platform libm only.
- #28, #141: neato and circo multispline ends 0.1pt off. These are GTS face-order ties, like #35.
- #154: fdp ortho around overlapping `fixedsize=shape` nodes.
- #101: `pack` with a node in two non-nested clusters. C prints `node … belongs to two
  non-nested clusters` and lays out on shared records (docs/porting/crashes.md). This is C's
  error path; it has no `wontfix` label and no What's left entry (#502).

None of these is a 1.0 blocker under the classes in F2.

**A cross-check, and its limits.** The whole corpus was also run through C 16.1.0 built on
Linux x86-64, with the port's math and Apple's `qsort`/`rand` interposed (the
`scripts/c-oracle-linux` set-up, run without Docker). Built with `CFLAGS=-O2` that build
reproduced the committed references on only 2,093 of 2,595 stable inputs. x86-64 clang fuses
no multiply-adds unless it is given `-mfma`, while the arm64 build fuses them. With `-mfma`,
which the Dockerfile now adds on x86-64 (#519), it reproduces 2,588. That is every input of
neato, twopi, patchwork and the render corpus (docs/porting/libm.md, "Linux x86-64"). The 7
left are 3 fdp layouts that depend on heap addresses, 2 NaN cases (a printed NaN sign, a
NaN converted to `int`), 1 GTS run-to-run order and 1 timeout. The reference stays C as built
on macOS arm64, but a new corpus input can now get its references on Linux. The exceptions,
which still need the maintainer's macOS set-up, are fdp inputs, inputs involving a NaN, and
the stock-C files (`e2e.json`, `structure.json`).

## Feature coverage against C 16.1.0

- **Engines:** all of C's: `circo dot fdp neato nop nop1 nop2 osage patchwork sfdp twopi`
  (`graphviz-pure -Kfoo` lists the same set as C's `dot -Kfoo`).
- **Output formats.** The port has 17 names: `canon dot dot_json gv json json0 plain
  plain-ext svg xdot xdot1.2 xdot1.4 xdot_json`, plus raster `png jpg jpeg jpe`. Of the formats
  in C's core plugin, the port lacks 15: `cmap cmapx cmapx_np eps fig imap imap_np ismap pic
  pov ps ps2 svg_inline svgz tk`. C's `vt` and `kitty` terminal plugins, and the cairo/gd
  formats (`pdf`, `gif`, ...), are not ported either. The source is the list C's `dot -Tfoo`
  prints with the full plugin directory. 1.0 adds `svg_inline` and `cmapx` (criterion F6);
  `ps` and `pdf` follow in 1.x ([D6](#decisions)).
- **Command line:** `graphviz-pure -?` prints C's usage text word for word, apart from the
  program name. `-x -y -s -q -O -l -c -P -G/-N/-E/-A`, the `-L` fdp options and the
  `-T fmt:renderer` forms all exit as C does on a test graph; `-c` succeeds where C fails
  because it has no plugin directory to write. 299 tests in `crates/graphviz-pure-cli/tests/cli.rs`
  cover the rest.
- **Attributes** are not measured separately. The evidence is the corpora above, plus C's own
  test graphs (379/379 per dot variant, README).
- **The C bug ledger** (`docs/c-bugs-ledger.md`) named code that no longer exists: `dot.rs`,
  `network_simplex_solve`, `NS_MAX_ITER`, `geom/src/splines.rs`. It also said `compound.c` and
  `pathplan` are not ported; both are (`dotgen/compound.rs` has `make_compound_edge`, and
  `geom/src/pathplan/` has all of `lib/pathplan`). This pull request corrects rows 001–010
  and 014.

## Non-goals

1.0 does not promise:

- **That every old `#NNN` reference resolves.** Issues and pull requests #165–#457 were
  opened by an agent account GitHub has since suspended, so about 736 references to them
  return 404. They stay as a historical record (#503, closed as not planned).
- **Identity with stock C on a platform's libm.** Every build uses the same math library, and
  differences from Apple's or glibc's libm are not bugs (docs/versioning.md, #40).
- **Identity with C built with Pango**, or with a C build other than the reference. Text is
  measured with C's built-in metric tables, as the reference build does.
- **Reproducing C's nondeterminism, undefined behaviour or crashes.** Where C's output depends
  on addresses, the clock, freed or uninitialised memory, the port gives one stable answer.
  Where C crashes or asserts, the port draws something sensible.
- **Pixel identity of raster output** (`-Tpng`, `-Tjpg`). C draws with cairo and Pango; the
  port rasterises its own SVG with resvg. Only the layout is C's.
- **Graphviz's other programs**: `gvpr`, `unflatten`, `tred`, `ccomps`, `sccmap`, `gvpack`,
  `acyclic`, `nop` as a program, converters and others. C 16.1.0 installs 36 programs in `bin/`;
  the port is `dot` and its library.
- **A newer Graphviz.** The reference stays 16.1.0. Moving to a newer release is a major
  version (docs/versioning.md).
- **Speed and memory.** 1.0 is about correctness; it has no performance target. On x86-64 the
  default build is slower than stock C on neato and sfdp (rnd2000: neato 70.2 s against 14.4 s,
  sfdp 1.80 s against 0.67 s) and parses with about 12× C's memory, while dot is faster than C.
  Closing and reversing that gap is the post-1.0 work (docs/roadmap/post-1.0.md, #514). 1.0 only
  has to leave room for it (D1).

## Decisions

Made by the maintainer on 2026-10-27. The exit criteria above carry the work each one implies.

| # | Decision | Rationale |
| :--- | :--- | :--- |
| D1 | **Only the facade (`graphviz-pure`) and `graphviz-pure-raster` are stable.** core, parser, geom, layout and render are implementation crates with no semver promise, pinned with `=`. The facade's `Graph` is an opaque handle with no public fields and no accessors. The CLI-only helpers (`RandState`, `with_rand_state`, `in_rand_run`, `FdpParms`, `set_y_invert`, `loadimage_installed`, `plugins`, `decoded`) leave the facade, and the CLI imports the internals. (A1, #520) | Post-1.0 speed and memory work needs the representation free to change. A cgraph/gvc-style compatibility layer can be added later if users ask (#529). |
| D2 | **The stable enums and options are `#[non_exhaustive]`, options get a builder, and the error is an opaque struct with a `#[non_exhaustive]` kind that raster shares.** (A6, #521) | New engines, formats, options and errors then stay minor versions. |
| D3 | **No serde on the stable API, and the derives come off core's graph types.** (A1, #520) | No runtime use, and a derive constrains every data-layout change. The JSON contract is `-Tjson`/`-Tjson0`. |
| D4 | **The MSRV may trail current stable by two releases** (about three months). `rust-version` is kept accurate, any release may raise it, and it is not a semver promise. (A3, #504) | The MSRV gives no speed; a small lag helps distribution packagers. |
| D5 | **No panic-site target for 1.0.** R1, R2 and the R3 ratchet are the gates. | Site-by-site changes gain no fidelity, and the post-1.0 iterator and arena rewrites remove sites anyway. |
| D6 | **1.0 adds `svg_inline` and `cmapx`; `ps` and `pdf` follow in 1.x**, `pdf` through svg2pdf behind a feature the library and wasm leave off. The missing formats are listed. (F6, #524; #528) | The two are small, byte-identical and requested automatically by Sphinx and the Python wrappers; the others would delay 1.0. |
| D7 | **A weekly scheduled fuzz run, plus the pre-release gate.** After 1.0: a differential round against C before each minor, and an OSS-Fuzz application. (R4, #527; #529) | It keeps the corpus alive, and the post-1.0 rewrites carry most of the fidelity risk. |
| D8 | **Document that layout cost is unbounded, as in C, and that services need their own limits**; a limits or cancellation API comes after 1.0. (S3, #510; #529) | A limits API designed now would be designed around internals that are about to change. |
| D9 | **Security fixes go to the latest 1.x minor only; 0.x gets none after 1.0.0.** (S3, #510) | It keeps the effort on one line. |
| D10 | **The JS API throws `Error` objects, returns arrays and objects, and ships a checked `.d.ts`.** (A8, #523) | Each change is breaking after 1.0. |
| D11 | **Document the crates.io raster libm exception for 1.0; fix it in 1.x.** (D-3, #509; #529) | Only raster pixels are affected, and pixel identity is already a non-goal. |
| D12 | **Signed off by the maintainer:** core and geom `EPL-2.0 AND MIT`, raster `EPL-2.0 AND OFL-1.1`, the other crates `EPL-2.0`, npm and JSR `EPL-2.0 AND MIT`, each with its licence texts. (S4, #525) | The metadata should match the code each package ships. |
| D13 | **`-V` prints `graphviz-pure - graphviz version 16.1.0 (graphviz-pure X.Y.Z)`.** (A9, #526) | The Python wrappers then parse it, and after 1.0 the line is part of the CLI contract. |
| D14 | **The library never writes to stderr; diagnostics are returned as values**, and the CLI prints them. (A7, #522) | Embedders get the warnings, and one process-wide global goes. |

Two facts behind D1 were stated loosely in the draft. `Graph` has 18 public fields of its own;
the 128 counts the public fields of the core structs reachable from it. `decoded` and `plugins`
are public modules of the facade, not re-exports, and `in_rand_run` is a CLI-only re-export too.

## How this was measured

All of it ran on Linux x86-64, with Rust 1.99.1 and clippy 0.1.99:

- `cargo build --release -p graphviz-pure-diff -p graphviz-pure-cli -p graphviz-pure-portable-libm`.
- **Fidelity:** `target/release/gv-diff e2e --list`, the eight layout ratchets as in
  `scripts/update-baselines.sh` (without `--update`), and `gv-diff render`.
- **Skipped inputs:** C, run with `GVBINDIR=/opt/graphviz-16.1.0/lutplugins
  scripts/dot-portable-libm.sh`, four times per skipped input; then the whole corpus with
  `GV_PORTABLE_LIBM=<portable-libm built --features apple-libc> gv-diff e2e --generate --runs 2
  --c-dot scripts/dot-portable-libm.sh`.
- **Panic sites:** `scripts/panic-sites.sh`.
- **API:** item counts from `RUSTC_BOOTSTRAP=1 cargo rustdoc -p <crate> --lib -- -Z
  unstable-options --output-format json`; `cargo semver-checks -p graphviz-pure
  --baseline-version 0.2.1` (cargo-semver-checks 0.51.0, installed outside the repository):
  202 pass, 58 skip.
- **MSRV:** `grep -rln '&& let ' crates/*/src` (33 files), and `cargo metadata --locked`
  for `jpeg-encoder` 0.7.1 (`rust_version` 1.87).
- **Dangling references:** every `#NNN` in tracked text and source files, outside
  `tests/golden/` and `vendor/`, checked against the full list of issues and pull requests
  from the GitHub GraphQL API.
- **Channels:** `gh release view v0.2.2`, and the crates.io, npm, JSR, PyPI and Wasmer APIs
  (read only).
- **Formats:** `graphviz-pure -Tfoo` and `dot -Tfoo` (C, full plugin directory).
